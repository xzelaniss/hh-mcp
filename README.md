# MCP-сервер для hh.ru API — 19 инструментов для ИИ-агента: вакансии, резюме, зарплаты

Если вы искали, как подключить hh.ru к Claude или другому ИИ-агенту, — этот сервер даёт агенту поиск по вакансиям и резюме, карточки работодателей, статистику зарплат и справочники hh.ru по России и СНГ. Спрашиваете «найди Python-вакансии в Москве от 250 000 ₽ на удалёнке» — агент возвращает готовый список с зарплатами и опытом, а не ссылку на выдачу. Поиск вакансий работает без токена; токен нужен только для базы резюме.

По умолчанию ответы приходят компактными сводками, удобными для LLM — передайте `raw: true` любому инструменту поиска или карточки, чтобы получить полный JSON hh.ru.

Часть серии [WWmcp](https://github.com/theYahia/WWmcp) от [@theYahia](https://github.com/theYahia).

## Два режима

| Режим | Что доступно | Нужен токен? |
|------|-----------------|:-------------:|
| **Без токена** | Поиск вакансий, вакансия по ID, похожие вакансии, работодатели, статистика зарплат, регионы, роли, отрасли, метро, справочники, подсказки, проверка токена | нет |
| **С токеном** | Всё перечисленное + поиск резюме, резюме по ID | да (`HH_ACCESS_TOKEN`) |

Токен выдаётся на [dev.hh.ru/admin](https://dev.hh.ru/admin). Важно: поиск резюме дополнительно требует аккаунт **работодателя** с **оплаченной подпиской на базу резюме** — токены соискателя и анонимные получают 403. Проверить возможности своего токена можно инструментом `validate_token`.

### Режим HTTP (Streamable HTTP)

```bash
# Из этого репозитория, после npm ci && npm run build:
# Сначала настройте защищённый режим и его переменные окружения (см. ниже).
npm start -- --http
# или
HTTP_PORT=8080 npm start -- --http
```

Эндпоинт: `http://localhost:3000/mcp` (POST) · Проверка состояния: `http://localhost:3000/health` (GET)

HTTP-режим stateless, по умолчанию слушает `127.0.0.1` с защитой от DNS-rebinding.
Требуется Node.js 22.12+ (для Render используйте 24). Доступны два защищённых режима:

- `MCP_AUTH_MODE=bearer` (по умолчанию): отдельный `MCP_SECRET_TOKEN` в env,
  клиент передаёт `Authorization: Bearer …`. Создайте секрет приватно командой
  `openssl rand -hex 32`. Подходит клиентам с настройкой заголовков.
- `MCP_AUTH_MODE=oauth`: совместимый с пользовательскими MCP ChatGPT OAuth через
  Auth0, обязательный allowlist владельца, RS256 JWT и discovery. Статический
  MCP_SECRET_TOKEN здесь не принимается. Отдельный шлюз или БД не требуются,
  но нужен настроенный Auth0 tenant.

В обоих режимах проверка выполняется до чтения тела и обработки MCP. Запрос без
правильного токена получает 401. Stdio не требует MCP-аутентификации. `GET /health`
остаётся публичным. Не помещайте токены в URL, исходный код, чат или логи.
`HH_ACCESS_TOKEN` нужен только для исходящих запросов к hh.ru и не заменяет MCP auth.
Файл `.env.local` автоматически не загружается.

Для внешнего доступа необходим HTTPS, `HOST=0.0.0.0` и реальный hostname в
`HH_ALLOWED_HOSTS`. Развёртывание и слияние PR требуют отдельного решения владельца.

### Подключение к ChatGPT и Render Free

См. **[пошаговую инструкцию OAuth + Render + ChatGPT](docs/chatgpt-render.md)**:
настройка Auth0, точные Build/Start Commands, env, Health Check Path и поля формы
«Добавить пользовательский сервер MCP». Выбирайте **OAuth** с заранее
зарегистрированными Client ID/Secret, а не смешанный или анонимный режим.
Реальное подключение требует отдельной настройки Auth0 и разрешённого развёртывания;
до этого проверены только автоматические тесты с имитацией внешних ответов.

## Переменные окружения

| Переменная | Обяз. | Описание |
|----------|----------|-------------|
| `HH_ACCESS_TOKEN` | нет | Bearer-токен OAuth 2.0. Нужен для эндпоинтов резюме (работодатель + оплаченная база резюме). |
| `MCP_AUTH_MODE` | нет | `bearer` (по умолчанию) или `oauth`. Режима без защиты нет. |
| `MCP_PUBLIC_URL` | в oauth | Канонический HTTPS origin сервиса, без `/mcp`. |
| `MCP_OAUTH_ISSUER` | в oauth | Точный HTTPS issuer Auth0 с завершающим `/`. |
| `MCP_OAUTH_CLIENT_ID` | в oauth | Разрешённый Client ID приложения ChatGPT в Auth0. |
| `MCP_OAUTH_ALLOWED_SUBJECTS` | в oauth | Разрешённые User ID (`sub`) Auth0 через запятую. |
| `MCP_SECRET_TOKEN` | в bearer | Отдельный секрет входящего доступа к `/mcp`. Передаётся как `Authorization: Bearer …`. |
| `HH_USER_AGENT` | нет | Свой `HH-User-Agent` (hh.ru его требует). Рекомендуемый формат: `your-app/1.0 (you@example.com)`. |
| `HTTP_PORT` / `PORT` | нет | Порт HTTP-режима (по умолчанию 3000). |
| `HOST` | нет | Интерфейс привязки в HTTP-режиме (по умолчанию `127.0.0.1`). |
| `HH_ALLOWED_HOSTS` | нет | Список разрешённых Host через запятую для HTTP-режима (по умолчанию loopback). |
| `HH_ALLOWED_ORIGINS` | нет | Список разрешённых Origin через запятую для HTTP-режима. |

См. [`.env.example`](.env.example).

## Инструменты (19)

Любой инструмент поиска или карточки принимает `raw: true` — тогда вернётся полный JSON hh.ru вместо компактной сводки.

### Вакансии

| Инструмент | Описание | Токен? |

| `get_similar_vacancies` | Найти вакансии, похожие на заданную | нет |

## Ограничение частоты запросов

Встроенный лимитер соблюдает ограничение API hh.ru — 5 запросов в секунду. Автоматический повтор с экспоненциальной задержкой на ошибках 429 и 5xx (до 3 попыток). Учтите: лимитер общий на процесс, поэтому в общем HTTP-режиме все клиенты делят один бюджет 5 запросов/сек.
